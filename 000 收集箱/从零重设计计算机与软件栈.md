# 正文

[[000 收集箱/新操作系统设计|新操作系统设计]] 里有一个判断：虚拟内存、硬件保护模式这些抽象层都是历史包袱，如果从一开始就用安全的托管语言构建系统，其中很多层是可以删掉的。把这个判断推到底，就是一个更彻底的问题——如果人类在计算机上的积累全部清零，硬件和软件栈应该长什么样？

要回答这个问题，得先回答一个更基本的问题：我们说的「安全」到底是什么，它应该由哪一层来保证。想清楚这一点之后，整个设计几乎是自动推导出来的。

## 安全的本质是一次检查，问题是检查放在哪

内存安全和类型安全归根结底是一件事：在每次访存、每条指令之前确认它合法，让程序要么按语义正确执行，要么显式失败，不存在第三种状态。而做这次检查，有四种放法：

- 放在编译期，由类型系统证明，运行时零开销——这是 Midori 的路线；
- 放在加载时和运行时，由验证器和托管运行时逐次检查——这是 JVM 和 BEAM 的路线；
- 放在每次访存时，由硬件电路拦截——这是 CHERI 的路线；
- 哪里都不放，靠程序员小心——这是 C 和传统操作系统的路线。

四种方案消除的是同一种东西，区别在于谁来付检查的成本、谁的生态要重写、抽象被冻结在哪一层。计算机史对这件事的投票结果很清晰：软件检查用很低的成本拿走了大部分收益，所以 JVM 赢了 Java 处理器；把 GC、进程、类型这些高层概念冻进硅片的机器——Lisp 机、picoJava、五代机——全部阵亡，因为抽象的保质期太短，软件一年一变，硅片十年一变。唯一还有机会的是 CHERI 这种把原语压到最低层的方案：硬件不理解「类型」和「进程」，只理解「指针有边界和权限」，于是连存量的 C 代码重新编译后也能被保护。

## 三条绕不过去的硬约束

第一是可信计算基无法消除。任何系统都必须有一个绕过检查的原点：GC 的写屏障、分配器、上下文切换、设备驱动，这些功能没办法用类型系统自己实现自己。JVM 留了 Unsafe，BEAM 留了 NIF，CHERI 留了特权代码和微码。就算把虚拟机整个硬化到 FPGA 上，原点也不会消失，只是从几万行 C 变成几万行 Verilog，而且硬件的错更难修。能做的只有把它压到最小、隔离起来。

第二是静态证明做不完。Rice 定理决定了「这段代码会不会越界」在一般情况下不可判定，所以完备的静态验证必然要么误伤合法程序，要么放过非法程序。出路只有两条：运行时逐次检查（硬件可以把这件事做得很便宜），或者要求程序带着证明来。这也意味着编译期证明再强，运行时和硬件仍然要保留最小的检查能力，「一切都在编译期解决」在理论上就不成立。

第三是内存安全不等于信息安全。边界检查保证数据不被越界读写，但 Spectre 证明了投机执行可以把检查的效果从缓存时序里泄漏出去——数据没有越界，秘密却丢了。硬件契约不管时序，软件打再多补丁也堵不上。

## 推导出来的设计

有了目标和约束，设计基本是推论，不需要发明什么。

硬件只做三件最低层的事。一是能力寻址：指针就是携带基址、边界和权限的能力，只能从权限更大的能力派生、不能凭空伪造；MMU 的地址空间隔离降级为性能优化，不再当安全边界用。二是一份没有未定义行为的指令集，并提供数据无关时序的模式，从架构契约上应对侧信道。三是字节寻址的非易失主存，内存即存储。GC、调度、进程一概不进硅片——硬件只回答一个问题：这次访存合不合法。

语言承担安全边界。一门语言从内核写到应用：所有权类型保证内存安全、消灭数据竞争；效应系统把 IO、网络、时钟都写进类型签名，一个函数能不能碰网络，看类型就知道。权限就是类型，授权就是传参。不留 unsafe 逃生舱，只留极少数被能力保护的原语模块，那些模块就是可信计算基本身。

操作系统缩成很小的一块。隔离被类型系统拿走了，资源管理被能力拿走了，剩下的内核只做能力调用、调度和内存授予三件事，小到今天就可以做形式化验证——seL4 已经证明这做得到。系统里没有进程和地址空间，隔离单元是类型安全的对象，创建一个的成本低到可以同时跑上百万个；也没有 root，没有「以当前用户身份」的默认权限，任何资源都要凭显式持有的引用才能访问。所有组件都按「随时可以被杀死、被重启」来设计，监督机制贯穿全栈——这本是 Erlang 的容错技巧，在这里变成系统默认。

持久层干脆消灭文件。对象默认就是持久的，堆即存储，没有 save、没有序列化、没有 ORM。今天生产系统里相当大比例的 bug 来自「内存里的世界」和「磁盘上的世界」这两个宇宙的同步，这个类别整体消失。底层用内容寻址的不可变存储，版本和去重是自然产物。

网络层把分布式当成默认语义。引用天然带位置：指向本机对象和指向另一个大洲的对象是同一套语义，分布是语言的一部分，不是后来加的 RPC 框架。身份就是公钥，跨机器的引用用密码学验证，「拿到 URL 就拿到权限」这种设计从第一天起就不存在。

## 最高原则是可演化性

上面这套设计没有一块是新东西：能力机器、单级存储、监督树、验证内核、一门语言写全栈，分别在 CHERI、Multics、Erlang、seL4、Oberon 里真实存在过。它们输掉的不是设计评审，而是路径依赖——切换到新世界的成本永远高于在旧世界上打补丁。

这引出比所有具体设计都重要的一条：新系统也会有三十年，也会积累出今天预想不到的错误假设。Midori 和 Lisp 机的教训不是设计错了，而是冻结了。所以整套栈真正不能违反的原则只有一条：硬件只强制最小原语，其他一切都必须是可以撤销、可以版本化、可以热替换的软件。换句话说，不要设计完美的层次，要设计可以替换的层次。

## 从哪一层开始做

真要动手的话，顺序是语言先行、硬件最后，理由有三个。

一是迭代速度和层级成反比：改一条类型规则以秒计，改内核以周计，改硅片以年计。而这套栈里所有悬而未决的问题——所有权怎么表达、效应怎么设计、能力怎么吊销、跨机器的引用是什么语义——全是语义问题，应该在试错最便宜的地方解决。二是编译器本来就是可信计算基的根，不管上面盖什么，最终都要信任它，先定义根，其他东西才有附着点。三是历史证据一边倒：Oberon、Midori、Erlang、Rust 全是语言先行；反例是 seL4，从内核出发，证明做得极好，结果是最可信的内核上跑着不可信的 C 代码。

具体分五步，每步都独立可用：

| 阶段 | 产物 | 运行在哪 |
|---|---|---|
| 0 | 核心演算（所有权、效应、能力、引用语义四个原语）加解释器，语义形式化 | 定理证明器 |
| 1 | 自举编译器和用户态运行时，隔离、监督、持久化全部用软件实现 | Linux 上的一个进程 |
| 2 | 整体编译成 unikernel，甩掉宿主系统 | 普通商用硬件 |
| 3 | 分布式引用语义，能力跨网络流动 | 上一步的集群 |
| 4 | 把稳定多年的语义做进 FPGA，再谈流片 | 语义稳定之后 |

还有一个必须提防的陷阱：语言不能在真空里设计。脱离真实系统的压力，效应系统会设计成没人能用的样子，能力纪律会在第一个真实驱动面前崩溃。所以第一步的正确做法是把语言和它的第一个严肃运行时当成一个项目做——每加一条语言规则，都要在运行时里找到一个非它不可的地方，让系统给语言挑错。
